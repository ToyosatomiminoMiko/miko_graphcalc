# 方程求解过程的展示设计

一句话结论:**过程需要的不是"更大的盒子",而是"另一页".** 解方程/看推导的时候,
用户不会去拖参数滑块,也不会去切视图开关--这些"手不动的东西"就是可以被遮挡的.
所以不改浮层格局,不去抢三维视口,而是把**右栏改成标签页**:一页放现有的
"参数 / 视图",另一页通高地放过程.

分期口径:**一期只做展示层,零内核风险**;步骤产物,三维联动,符号求解内核
留到二/三期,边界见 [第 6 节](#6-分期与数据来源).

配套阅读:[教学化改造路线图](teaching-roadmap.md) 的 B1(步骤化求导)与 B5(本设计).

## 1 问题

### 1.1 空间实测

数字来自 `src/config/uiConfig.ts` 的 `UI_CONFIG.panel` 与 `css/layout.css`:

| 区域 | 现状 | 来源 |
| --- | --- | --- |
| 三维视口 | `position:absolute; inset:0`,铺满全窗口,所有面板浮在它上面 | `css/layout.css` `#viewport` |
| 左栏(源码) | 宽 220–875px(默认 300),通高 | `#left-panel` |
| 右栏(参数/视图) | 宽 220–875px(默认 300),**通高** | `#right-panel` |
| 底栏(对象清单) | 高 **160–640px**(默认 240),折叠后 40,夹在左右栏之间 | `#bottom-panel` |
| 底栏内部 | `1fr 1fr` 两栏(实体 \| 求值),各自纵向滚动 | `#object-panel` |
| 过程现状 | 求值条目里一个 `<details>`,展开后一行一条 KaTeX | `evaluationDom.ts` / `.eval-detail-body` |

底栏可用高度:`640 − 标题栏(约 33) − 面板内边距(16) − 栏标题(约 31) − 列表内边距(12)`
≈ **548px**.公式单行高度:KaTeX 字号 1.5em(24px)继承 body 行距,简单递等式
一行约 34px,加上 `.eval-detail-body` 的 3px 间隙约 **37px**;一旦出现分式/根号,
一行可达 **55–70px**.于是:

- 全是简单行:**约 14 行**见底;
- 含分式:**约 8 行**见底.

宽度同理:默认 1920px 屏,中间区 `1920 − 300 − 300 = 1320px`,底栏两栏各
**约 646px**;`sin`/`ln` 复合函数的链式展开很容易超出这个宽度,只能靠
`.eval-detail-line` 的横向滚动承接.

同一块屏,右栏通高可用的高度是 `100vh − 标题栏与内边距`,1080p 下约
**1020px ≈ 27 行简单式**--是底栏上限的两倍,而且**不与实体清单抢列宽**.

### 1.2 "把 footer 拖高"解决不了

1. **高度写死**:`footerMaxHeight: 640`,2K/4K 屏也还是 640,垂直空间白白浪费.
2. **宽度对半**:`#object-panel` 是 `1fr 1fr`,过程只能占一半,长等式必然横滚.
3. **共用容器**:过程与实体清单挤在同一个滚动区,展开一条就把别的条目挤出视野;
   而且行重建(`KeyedRowList` 的整行替换)会带来滚动位置跳动.
4. **没有"步"这个概念**(真正的缺口,见 1.3).

前三条是空间问题,第四条是设计问题.只解决前三条,得到的是一面更长的文本墙.

### 1.3 真正的缺口是交互模型

现在"看过程"只有一档:一次性把细节全展开.教学要的却是:

- **当前走到第几步**,而不是整段一次性给出;
- **这一步的依据**(链式法则 / 因式分解 / 同底数幂合并),而不只是等号两边;
- **前后翻步**(板书节奏由讲者控制,不由滚动条控制);
- **几何跟着变**(拖动 `h->0` 时割线变切线,分割加细时黎曼矩形变密).

最后一条是本项目区别于"能解方程的 CAS"的地方,也是这条路线上唯一值得
不计成本做的部分.

## 2 设计原则

| # | 原则 | 含义 |
| --- | --- | --- |
| P1 | **遮挡"手不动的东西"** | 读推导时不会调参/调视图,所以右栏现有的那一页此时没有信息增量,让位给过程.不新增浮层,不压缩三维视口 |
| P2 | **保守式新增** | 一期只碰展示层:不改 Rust,不改 `ir/types.ts` 既有字段语义,不新增 DSL 语句.求解内核是"不可避免但必须分期"的事,不许一步到位 |
| P3 | **三级披露** | 短过程留在原地(零改动),长过程才进过程页.判据是纯函数,阈值进配置 |
| P4 | **文案与数据分离** | 步骤的依据文案(如"链式法则")是数学内容,放纯数据模块,不硬编码进渲染逻辑(与 `src/config/uiConfig.ts` 的"只放纯数据"同一约定) |
| P5 | **可单测** | 披露判据,步骤分区,翻步状态机都是纯函数/纯状态转移;碰不到 DOM 的部分必须能在测试里断言(路线图改造原则 4) |

## 3 版面:右栏标签页

### 3.1 目标结构

```text
<aside id="right-panel" class="panel">
  <header class="panel-header">          ← 折叠时唯一保留的一层
     <div id="right-tabs" role="tablist">  ← 新增:两个标签
        [参数 / 视图]  [过程]
     </div>
     <button data-panel-toggle="#right-panel">收起</button>
  </header>

  <div id="right-page-params" role="tabpanel" data-tab="params">   ← 新增:页1
     <section id="params-panel"></section>       (现有)
     <section id="diagnostics"></section>        (现有)
     <div id="right-splitter"></div>             (现有)
     <header class="panel-header">视图</header>  (现有)
     <section id="view-controls"></section>      (现有)
  </div>

  <div id="right-page-process" role="tabpanel" data-tab="process" hidden>  ← 新增:页2
     <section id="process-panel"></section>
  </div>

  <div class="resize-handle resize-handle-left" data-resize-panel="right-panel"></div>
</aside>
```

要点:**两页的内容各自包一层**.原因见 3.2 的第 1 条--`PanelController` 的折叠
实现是"隐藏除承载开合按钮的那个 header 以外的全部直接子元素",包一层之后
页级显隐与折叠级显隐互不干扰,各自只有一个写入点.

标签页用 `role="tablist"` / `role="tab"` / `role="tabpanel"`,**不复用**
`ui/widgets/Segmented.ts`:后者的语义是"切换按钮"(`role="group"` +
`aria-pressed`,每个按钮都能 Tab 到),而标签页的键盘约定是"整组一个 Tab
停靠点 + 方向键在组内移动 + `aria-selected` + `aria-controls`,需要 roving
tabindex".语义不同强行复用会把读屏与键盘行为做成四不像.新写一个
`src/ui/widgets/Tabs.ts`,样式仍归 CSS,句柄契约(`element` / `get` /
`onChange` / `dispose`)与其他控件保持一致.

### 3.2 必须处理的四个耦合点

这一节是本次改动**唯一有真实风险**的地方,四处都在现有控制器里,漏一处就是
上一轮 UI 审查里那类"模型一套,DOM 一套"的缺陷(UI-P3.3).

1. **折叠语义**.`PanelController._applyLayout()` 会遍历面板的直接子元素,把
   非 header 的全部设成 `display:none`.标签页栏必须**放进那个 header 内部**,
   否则一折叠就再也切不回来;两页各自包一层 `<div>`,折叠时整页一起隐藏,
   不必给折叠逻辑加"哪些子元素算内容"的清单.

2. **分隔条的比例基准**.`RightSplitController.computeSplitRatio()` 现在拿
   `#right-panel` 的矩形当基准(理由是"参数区是右面板第一个子元素,顶边重合").
   加了标签页栏之后这条前提失效:参数区的顶边比面板顶边低了一个标签栏.
   改法是**把基准换成页容器**(`#right-page-params`),并在页容器上恢复
   `display:flex; flex-direction:column; flex:1; min-height:0`
   (`#params-panel { flex: 0 0 var(--right-split-basis) }` 的参照系随之从
   "右栏高度"变成"页高度",语义更准确).同时过程页激活时,`#right-splitter`
   与 `#params-panel` 整组退出布局,不能让 `flex-basis` 参与计算.

3. **宽度的唯一写入点**.`--right-panel-width` 只有 `PanelController._applyLayout`
   一个写入点,这条不变量不能破(UI-P3.3 的教训).因此**过程页需要更宽的栏宽**
   这件事不能由标签页控制器直接写 CSS 变量,只能走 `PanelController`:

   - 建议:把 `sideWidths` 从"每个面板一份"扩成"每个**宽度组**一份",分隔条上
     加 `data-resize-group`(参数页 `params` / 过程页 `process`),控制器按当前
     激活的组写宽度.切页 = 切宽度,用户的调整按页记住.
   - 备选:只给一个全局宽度,进入过程页时若不足可读下限就临时抬到下限,退出时
     还原.改动更小,但"拖动被吞掉"的行为需要用测试钉死.
   - 降级:不做按页宽度,只把标签栏做成可双击自动加宽.

4. **行末按钮的契约**.过程入口按钮要挂在求值条目行末,但
   `createObjectRow(rowClass, toggle)` 只容得下**一个**按钮(显隐按钮),而且
   显隐按钮刻意不在 `<summary>` 里(点了不会开合).加第二个按钮必须把该函数
   的参数从"一个元素"改成"一个行末动作容器",并同步 `EntityItem` /
   `EvaluationItem` 两侧调用点与 `ObjectListController.test.ts` 的手写 DOM 桩.
   这是本次唯一要动的共享件,改完必须是一次纯签名扩展,不改变显隐按钮的
   位置语义(仍在行末,仍不在 `<summary>` 内).

### 3.3 宽度策略

右栏默认 300px 对递等式偏窄:一条 `sin(a·x)` 的链式展开即使不带分式也要
400–500px.建议:

- 过程页的默认宽度取 **420px**,夹取范围沿用现有的 220–875;
- 宽度**按页保存**(3.2 第 3 条的建议方案),切回参数页时还回原来的宽度;
- 标签栏上加"板书模式":一键把右栏推到上限并折叠左栏与底栏.它需要
  `PanelController` 暴露一个"按 id 折叠/设宽"的编程入口--**一期不做**,先
  手动拖;二期再评估(它会让折叠态多一个写入路径,必须与 `_applyLayout`
  合并成同一处).

### 3.4 退化

- 视口宽 < 900px(或右栏拖到上限仍不足):过程页退化为**覆盖三维视口的整页**
  (`#right-panel` 临时 `left:0`),这是同一份内容换一套几何,不是第二套实现;
- 视口高 < 600px:过程页保留滚动,不改结构;
- 折叠态:沿用现有折叠,标签栏与标题一起隐藏,只剩"展开"按钮.

## 4 内容:过程视图

### 4.1 一行一步的递等式

每一行是"**左边关系符 + 一行 KaTeX + 右边依据徽章**",垂直排列,序号在左:

```text
 1   x^2 - 5x + 6 = 0                       原式
 2   (x - 2)(x - 3) = 0                     因式分解
 3   x - 2 = 0  或  x - 3 = 0               零积律
 4   x = 2  或  x = 3                       移项
```

实现上沿用现有约定:一行一个 LaTeX 字符串,交给 `FormulaView` 排版,
**公式不换行**,排不下时由该行横向滚动(KaTeX 换行会破坏公式语义,这是
`evaluationLatex.ts` 已经写明的取舍).与现有细节行的区别只有两点:多了序号与
依据两列,以及当前步高亮.

### 4.2 步骤分类:求导法则 vs 代数化简

路线图 B1 的风险①明确要求:**化简规则与求导法则不是一个概念**,混在一起学生
会把"同底数幂合并"当成求导.因此每一步带一个 `kind`:

| kind | 展示 | 例子 |
| --- | --- | --- |
| `rule` | 强调色徽章 | 链式法则,积法则,商法则,幂法则 |
| `algebra` | 中性色徽章 | 因式分解,通分,移项,同底数幂合并 |
| `definition` | 虚线徽章 | 导数定义式,导数定义代入 |
| `numeric` | 等宽数字 | 数值代入,差商校验(路线图 T8) |

一期没有内核产物时,`kind` 由数据源标注;三期由 Rust 步骤产物给出,UI 不变.

### 4.3 当前步与交互

- **当前步**:高亮一行,其余降饱和度.点击任意行也可跳转.
- **翻步**:`上一个 / 下一个` 两个按钮 + 键盘左右方向键.键盘走
  `KeyboardController.register`(项目约定"唯一键盘出口",见 `DslApp.start()`),
  控制器自己**不绑** keydown.
- **连续播放**(可选,一期先不做):离散步进用 `AnimationPlayer` 现有的时间轴
  有点重;一期只做离散前后翻.
- **状态机**(可单测):`{ steps, index }`,转移函数 `next/prev/goto` 夹取到
  `[0, steps.length-1]`,越界是 no-op 而不是回绕.这条单独放一个纯模块,
  与 DOM 无关.
- **出口**:视图对外只暴露 `onStepChange(index)`.一期的消费者只做高亮与滚动;
  二期的消费者换成"把第 k 步写成一个虚拟参数"去驱动几何(见第 6 节).

### 4.4 空状态与上限

- 没有可展示的过程时给一句明文("该对象没有可展开的过程"),不要给空盒子.
- 步骤上限:超长过程必须**截断并注明**,不能无上限铺开.上限值进
  `uiConfig.ts`(纯数据),与 `FormulaView` 的模板缓存上限(512)分开算:
  步骤行的 LaTeX 键是"表达式签名 × 步数",是有限集合,不需要扩容,但需要
  上限本身有明确语义.
- 隐藏对象(`enabled === false`)不参与计算,也就没有数值可展示:过程入口
  置灰并给理由,与"已隐藏,不参与计算"的现有文案口径一致.

## 5 三级披露与阈值

| 级别 | 位置 | 长度预算 | 状态 |
| --- | --- | --- | --- |
| L0 摘要行 | 条目第一行 | 1 行 | 已有,不动 |
| L1 行内展开 | 条目 `<details>` | ≤ N 行 | 已有,保留给短过程 |
| L2 过程页 | 右栏"过程"标签页 | 通高 | 新增 |

判据是一个纯函数:

```ts
// 细节行数超过阈值就走 L2;阈值进 UI_CONFIG,不进代码字面量
export function needsProcessPage(lines: readonly EvaluationDetailLine[]): boolean
```

- 短过程(梯度:符号展开 + 数值 + 球坐标回显,通常 3–5 行)继续留在
  `<details>`,用户不必切页,老路径一行不改;
- 长过程(逐步求导,求解,分割加细)在条目上出现"过程"按钮,点击后
  **右栏切到过程页并载入该条目**;
- 阈值 N 的默认值由实测定(建议 6):它与 1.1 的 14 行上限配合--留在 L1 的
  最多占掉不到半个底栏.

## 6 分期与数据来源

| 期 | 范围 | 数据来源 | 是否动 Rust | 是否动 IR |
| --- | --- | --- | --- | --- |
| **一期** | 右栏标签页 + 过程视图 + 三级披露判据 + 条目"过程"入口 | 现有 `analysisLatexDetails` / 积分与求交的细节行,按递等式口径重组 | 否 | 否(只读现有字段) |
| **二期** | 步骤索引驱动几何:割线->切线,黎曼矩形加细,交点高亮 | 一期已有的 `onStepChange` 出口 | 否 | **只新增**字段(如 `stepHighlights`),不改既有字段语义 |
| **三期** | 保守式求解内核:独立步骤产物类型 + WASM 入口 | 内核产物替换一期数据源 | 是 | 只新增 |

三点说明:

1. **一期不做三维联动**,但一期的接口按二期的需要定(`onStepChange` 只发
   索引).这样二期**不需要重做前端**,只接一个消费者.
2. **二期走现有参数链路**,不新建渲染通道:把"第 k 步"当成一个虚拟参数,走
   `CompileController.refresh(params)` -> `RenderController.applyScene(scene,
   changedParams)`,复用既有的缓存与 latest-only 异步调度.这符合项目的
   "复用,不要重建.缓存,不要重算"口径.
3. **三期的步骤产物必须是独立类型**,不是 `Expr`(路线图 §7.1 的既有结论:
   不要把符号引擎内部表示泄漏成项目级 API).三期只换数据源,UI 层零改动--
   这正是"展示层先行"的价值.

## 7 缓存与复用

| 复用什么 | 怎么复用 | 不要做什么 |
| --- | --- | --- |

## 9 风险与降级

## 10 明确不做

- **不新增浮层面板**去抢三维视口(那会破坏"面板浮在视口上"的现有格局,
  且与 P1 相反);
- **不改 `DslApp` 的编排职责**(它仍是组合根,新控制器在 `start()` 里装配一次);
- **不在过程页里内联 Markdown 讲义**:讲解文案属于 `docs/`,不重复第二份
  (路线图 §7.2 第 1 条);
- **不落 localStorage**:界面偏好与当前步都不持久化,刷新回默认(与
  `RightSplitController` 的既有约定一致);
- **一期不做播放动画,不做练习判定,不做进度**;
- **不做二值的"过程对不对"判定**:需要时按路线图 C1 的第三态口径走.
