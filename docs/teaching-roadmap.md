# 教学化改造路线图

本文件规划 GraphCalc 从"能看结论的可视化器"走向**教学工具 + 自学教材**的
分阶段任务.定位已确认:**教学侧优先,自学侧同步跟进**.

结论先写在最前面:**教学化的瓶颈不是渲染,是"过程不可见"与"题不在库里".**
项目的三维渲染,异步计算链路,五种积分法可视化都已经到位;真正挡住课堂的
是符号引擎只暴露最终结果,`example/` 没有加载器,默认场景对新手不友好.

- 面向学生/使用者的部分见 [第一部分](#第一部分现状解剖)到
  [第四部分](#第四部分教学要素设计);
- 面向自己/后来者学架构的部分见 [第五部分](#第五部分自学侧)与
  [第七部分](#第七部分风险与反模式);
- 每项任务用 `T` 编号,依赖关系与推荐执行顺序见
  [第三部分](#第三部分分阶段路线图).

## 工作量口径

本文用**半天**为工作量单位(理想连续投入,含自测,不含等待 CI).

| 记号 | 含义 |
| --- | --- |
| `0.5d` | 纯文档/配置,无逻辑改动 |
| `1–2d` | 单文件逻辑改动 + 测试 |
| `3–5d` | 跨层改动(TS + 可能 Rust),需要新增契约 |
| `1w+` | 触碰 Rust 符号引擎公开面,需要设计决策 |

## 1.2 数学表达力缺口

按"课堂会不会用到"排序,不按实现难度.

| # | 缺口 | 现状证据 | 教学影响 |
| --- | --- | --- | --- |
| G1 | **求导过程不可见** | `math_rs::symbolic_derivative(expr, var)` 只返回化简后的字符串 | 只能讲"结果是",讲不了"为什么";`derivative_rules.scad` 只能用并列对照代替推导 |
| G2 | **无极限 / ε-δ** | 语法与内核均无 `limit` 概念 | 导数的定义式,连续性,收敛都讲不了 |
| G3 | **无方程/不等式求解** | 无对应语句;`implicit` 只画等值线,不解 | 无法出"解不等式"类习题 |
| G4 | **函数族偏窄** | `src/math/math_rs/src/builtins.rs` 无 `floor`/`ceil`/`min`/`max`,无分段 | 分段函数,取整,最值问题全是盲区 |
| G5 | **体积对象不可求导** | `analyses.ts` 明确报"暂不支持 box/conic 体积对象" | `box`/`cone`/`cylinder` 的梯度演示缺席 |
| G6 | **`region` 只支持 x 型带** | `src/compiler/dsl/objects/build.ts` 文件头标注 V1 限制 | 极坐标区域,y 型区域,多边界区域无法演示 |

> **不要试图补成完整 CAS.** README 已宣告"作为 CAS 是不完全的",这是定位
> 而不是缺陷.课程设计应顺着这个边界走:只讲能算的,把算不了的留成
> "下一版再说".补全 CAS 是无底洞,见第七部分.

## 1.3 教学动线缺口

比数学缺口更急,因为**成本低,收益直接**.

| # | 缺口 | 现状证据 | 影响 |
| --- | --- | --- | --- |
| D1 | **`example/` 没有加载器** | 全仓库 `grep` 不到任何 `.scad` 读取代码;`dist/assets` 里无 `.scad` | 学生必须手抄文件内容,离线状态下更是只能靠记忆 |

| D3 | **无练习模式** | 无题面/答案/判定机制 | 只能演示,不能练 |

## 第二部分:改造原则

写在这里是为了防止教学化改造变成新一轮重构爆炸.

1. **不碰编排层.** `src/app/DslApp.ts` 是编译/渲染/异步计算/UI 四条线的
   交汇点.教学改动一律走"新增示例素材 + 新增 UI 叶子组件 + 新增文档",
   不从编排层长出新分支.
2. **不改 `ir/types.ts` 的既有字段语义.** 它是语言层与渲染层的唯一稳定
   契约.新增字段可以(如 A3 需要补充展示数据),改旧字段语义不行.
3. **不改 `src/wasm/*`.** 那是 `wasm-pack` 产物且被 `.gitignore` 忽略.
   内核行为变更一律改 `src/*_rs` 源码后重跑 `npm run build:wasm`.
4. **每个教学特性必须可单测.** 项目现有 46 个测试文件是安全网;新增
   逻辑若无法写成测试,说明它被放在了错误的层(大概率是塞进了 DOM 代码).
5. **UI 文案与数据分离.** 课程文案,学习目标,思考题都应放在纯数据文件
   (可参考 `src/config/uiConfig.ts` 的"只放纯数据"约定),不要硬编码进
   渲染逻辑,否则改一句文案要动代码.
6. **任何"要不要迁进 Rust"的判断必须有实测数字.** 口径见
   [docs/wasm-boundary-cost.md](wasm-boundary-cost.md):边界固定开销
   ~1.1 µs,`CompiledEvaluator` context 占求值成本 94–99%.凭感觉搬会亏.

## 阶段 B:需要新增契约(TS 为主,少量 Rust)

### B1 步骤化求导(教学质量的分水岭)

| 项 | 内容 |
| --- | --- |
| 问题 | **G1,本项目从"可视化器"升级为"教具"的唯一关键项**.当前 `symbolic_derivative` 只给最终化简结果,求导法则(链式/积/商/幂)的应用过程被 `simplify` 吃掉了 |
| 现状证据 | `src/math/math_rs/src/symbolic/derivative.rs`,`simplify.rs`,`builtins.rs`(已实现完整的规则表:`derivative_sin/cos/tan/asin/...`,`derivative_log_base`,`expand_sec/csc/cot`,`expand_deg` 等),但 `pub(crate)` 级别,公开面只有字符串进出口 |
| 改动(四步,建议分 PR) | ①**Rust 侧新增产物类型** `DeriveStep { rule: &'static str, before: Expr, after: Expr }`,让求导递归在每一步记录所用法则;②**新增序列化**:把步骤链打印成 `Vec<String>`,每条形如 `d/dx[sin(u)] = cos(u)·du/dx (链式法则)`;③**新增 WASM 入口** `symbolic_derivative_steps(expr, var) -> Vec<String>`(独立函数,不改 `symbolic_derivative` 的签名,保住既有 116 个 Rust 测试);④**前端展示**:在 `src/ui/formula/FormulaView.ts` 附近新增步骤行,复用 KaTeX 渲染(LaTeX 能力 `symbolic/latex.rs` 已有) |
| 依赖 | T8(用于交叉验证数值正确性) |
| 工作量 | `1w+`,建议拆成 ①+②(内核,3–5d),③(边界,0.5d),④(UI,2–3d) |
| 验收 | 对 `sin(a*x)`,`x^2*exp(x)`,`ln(cos(x))`,`1/x` 至少四个案例,步骤链**每一步的首尾相接**(上一步的 `after` 等于下一步的 `before`),且最后一步等于现有 `symbolic_derivative` 的输出;Rust 侧新增逐案例断言测试 |
| 风险 | ① **`simplify` 会掩盖法则归属**:化简规则(如"同底数幂合并")与求导法则不是一个概念,步骤链中需明确区分"求导法则"与"代数化简"两类步骤,否则学生会把化简当求导.② **不要改 `Expr` 的公开性去图方便**,那会把符号引擎的内部表示泄漏成项目级 API.③ 步骤粒度是设计决策:是"每个函数一个步骤"还是"每次递归一个步骤",**先定粒度再写代码**,否则返工.④ 表达式树深度上限(`parser.rs` 的 `MAX_TREE_DEPTH`)会限制可展示的步骤数,超深表达式要么截断要么拒绝,需明确语义 |
| 降级 | 只对**一元复合函数**输出步骤(链式法则一条线),积/商法则仍只给结果.覆盖课堂 80% 需求而成本减半 |

## 阶段 C:长期/探索

### C1 练习判定

给定题面与学生的 `.miko` 代码,自动判定结果是否等价.**建议用"数值对拍"
而非符号等价**:在同一组采样点上比较两条曲线的函数值,容差内一致即通过.
符号等价判定是难问题,数值对拍 20 行代码就能做,而且与项目
`CompiledEvaluator` 的既有能力天然契合.

| 项 | 工作量 | 风险 |
| --- | --- | --- |
| `3–5d` | 容差与采样点选择会让判定出现假阴/假阳;需要"判定不确定"这个第三态,不要做二值判定 |

### C2 课程进度与持久化

| 项 | 工作量 | 风险 |
| --- | --- | --- |
| `1–2d` | 项目当前**刻意不使用 localStorage**(`src/config/uiConfig.ts` 明确"也不落 localStorage",唯一真相源是配置文件).进度持久化会打破这个约定,需先确认这是有意的策略还是历史遗留 |

### C3 步骤化积分的调研

先做**可行性调研**,不写实现.核心问题:现有积分是数值路径
(`math_rs::integral_core` 等),符号积分(原函数)是另一套完全不同的能力,
且符号积分不可判定(里施算法覆盖面有限).**调研结论大概率是"不做"**,
但把结论写进文档能避免以后重复讨论.

## 4.2 按主题的教学顺序(建议)

沿用现有文件,不重命名.顺序由 `example/README.md` 的表格承载.

| 序 | 主题 | 现有/新增文件 | 核心结论 |
| --- | --- | --- | --- |
| 1 | 函数与参数 | `object_addition.scad` + 新增最小场景 | 表达式即图形,参数即滑块 |
| 2 | 导数定义 | 新 `secant_to_tangent.scad` | 割线极限 = 切线斜率 |
| 3 | 求导法则 | `derivative_rules.scad` | 积/商/链式的对照 |
| 4 | 导数函数图像 | `derivative_graph.scad` | f' 本身是函数 |
| 5 | 一元点分析 | `derivative_curve.scad` | 切线/法向的几何意义 |
| 6 | 偏导与切平面 | `partial_derivative_surface.scad` | 临界点处切平面水平 |
| 7 | 梯度与隐式场 | `sphere_gradient.scad` | 梯度垂直等值面 |
| 8 | 散度与旋度 | `divergence_vector_field.scad`,`curl_vector_field.scad` | 源汇 / 旋转 |
| 9 | 定积分与黎曼和 | 现有 `integral` 示例 + 五种方法对照 | 分割加细取极限 |
| 10 | 重积分与区域 | `double_integral_region.scad` | 积分域是平面区域 |
| 11 | 求交 | `intersection_line_curves.scad`,`intersection_surfaces.scad` | 方程的几何解 |
| 12 | 变换与动画 | `animation_box_rotations.scad` | 矩阵即变换 |

> 第 9 课是本项目**最有教学差异化优势**的一课:五种积分法的可视化在同类
> 工具里并不常见(`riemann:left/right/mid`,`trapezoid`,`simpson`,
> `lebesgue`).建议把重心放这里,并做成 `docs/` 里的重点文档.

## 4.3 习题设计约束

出题前逐条自查(防止出无解题):

- [ ] 表达式只用 `builtins.rs` 里有的函数(没有 `floor`/`min`/`max`/分段)
- [ ] 求导题不含 `abs` 的不可导点(有 `sign`,但语义是弱导数)
- [ ] 区域题只用 x 型带(`region` V1 限制)
- [ ] 求导题不引用 `derivative` 的产物(对象相加明确不支持)
- [ ] 体积对象的梯度题不用 `box`/`cone`/`cylinder`/`frustum`(G5)
- [ ] 数值积分题给出方法名与分段数(不同方法结果不同,避免答案争议)

## 第七部分:风险与反模式

## 7.1 明确不要做的事

| 反模式 | 为什么 |
| --- | --- |
| **补全 CAS**(符号积分,方程求解,极限,级数) | README 已把"不完全"定为定位.补全没有终点,且会稀释已有的可视化优势 |
| **新增 `limit` 语句** | 是完整 CAS 的入口.数值演示(阶段 B2)已满足课堂教学 |
| **改 `src/wasm/*`** | 产物且被 gitignore;改动会被下次构建覆盖 |
| **在 `DslApp` 上继续长功能** | 它是四条线的交汇点,教学特性在此堆积会重现项目早期"看不懂"的问题 |
| **改 `ir/types.ts` 既有字段语义** | 语言层↔渲染层的唯一稳定契约,语义漂移会同时影响所有渲染器与测试 |
| **为教学给 `Expr` 加公开 API** | 会把符号引擎内部表示泄漏成项目级 API(B1 的步骤产物应是独立类型,不是 `Expr`) |
| **做"二值"练习判定** | 数值对拍必然有边界情况,必须留"判定不确定"第三态 |
| **未经测量就把计算迁进 Rust** | 口径见 `docs/wasm-boundary-cost.md`;边界固定开销 ~1.1 µs 在逐点调用场景会主导成本 |

## 7.2 隐性风险

1. **文档双份维护**.教学文案一旦同时出现在 `README`,`docs/`,文件头注释
   三处,必然漂移.约定:文件头放"这一课讲什么",`docs/` 放"为什么这样",
   `README` 只放索引与回链,不复制内容.
2. **注释里的数学错误比代码错误更隐蔽**.项目已有高质量注释,但教学改造
   会新增大量数学断言,每条都应可用数值或符号对拍验证.
3. **首屏体积**.主 chunk 已 1.04MB,全站 4.5M.示例内联,步骤展示,KaTeX
   步骤行都会加码,每次新增都要实测首屏.
4. **顺序依赖 D2->D1**.简化默认场景必须晚于示例加载器,否则会丢失现有
   默认场景的演示能力.
5. **阶段 A 的"零风险"只对内核成立**.T5/T6 会动 `index.html` 与 UI 叶子
   组件,仍需跑 `npm test` 与手工验证页面.
